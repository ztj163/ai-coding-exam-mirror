小型客户沙龙 · 会议签到应用

一、业务背景

市场部每个季度办一场小型客户沙龙：30—50 位客户，全部是邀约制——由客户经理提前邀请，客户在 CRM 里留有姓名、手机号、公司、邀约人，市场部把这些邀请记录导出成名单。

现在的现场签到是纸质签到表：客户到场后在表格上找自己的名字、签字，工作人员在旁边勾选。这个流程问题很多：

  • 客户多的时候要排队找名字，签到台拥堵；
  • 字迹潦草、漏签、代签都无法核对；
  • 客户经理在现场没法知道"我邀请的客户到了几个"；
  • 活动结束还要把纸质表格手工录入 Excel，费时且容易出错；
  • 有人重复签到、或把没受邀的朋友带来，签到表上也看不出来。

市场部希望做一个手机端签到应用：把签到二维码贴在签到台和桌卡上，客户到场后用手机扫码打开签到页，输入报名时预留的手机号，系统识别出他的身份（姓名/公司/客户经理），客户确认后一键签到；签到时间由系统自动记录，同一个人只能签到一次；没在邀请名单里的现场来宾可以走"现场登记"。同时客户经理要能在手机上随时看到实时到场情况。

二、任务目标

做一个手机端会议签到应用，完成：身份识别 → 签到 → 排重 → 实时统计。

验收口径：用手机打开签到页，输入名单里的手机号 → 页面显示正确的姓名与公司 → 点击签到成功；再换一种手机号写法（加空格/横线、+86、全角数字）提交，必须被识别为同一个人并拒绝重复签到；工作人员用口令打开总览页，能看到"应到 / 已签 / 未到 / 到场率"；重启程序后数据仍在。

三、功能需求

编号需求验收要点
FR-1移动端签到页手机浏览器直接打开（响应式、viewport、触屏可用）；客户输入手机号即可自助签到，无需登录
FR-2身份识别按手机号匹配邀请名单，返回该客户的姓名、公司、邀约人；未匹配到要给出明确提示并引导现场登记
FR-3手机号归一化客户填写的手机号可能带空格、横线、+86/86 前缀、全角数字，必须归一化后再匹配（例：138 0000 0001、138-0000-0001、+8613800000001、１３８０００００００１ 都是同一个人）
FR-4签到与自动记录时间签到时间由服务端生成（ISO 8601 含时区）；姓名/公司以名单为准，不采信客户端提交的姓名
FR-5排重同一手机号只能签到一次；重复签到返回 409 并给出首次签到时间；任何写法变体都必须被判为同一人
FR-6现场登记未在名单中的来宾，填写姓名（公司选填）后可现场登记，签到类型标记为 walkin；同样受排重约束
FR-7名单导入与清洗启动时读取随题名单 CSV：① 手机号无法识别（缺失/非法）的记录不计入应到人数，但要在日志中告警；② 同一手机号（归一化后）重复出现的邀请记录只算一位受邀人；姓名/公司需去掉首尾空白（含全角）
FR-8数据持久化邀请名单与签到记录都落盘（SQLite / 文件均可）；重启后应到人数、签到记录、排重规则都仍然生效
FR-9工作人员端（口令保护）提供实时总览：应到人数、受邀已签到、现场登记、未到场、到场率、已签到明细与未到场名单；接口与页面必须口令校验，无口令或口令错误返回 401
FR-10隐私保护明细中的手机号必须脱敏（如 138****0001）；未授权请求不得返回客户名单
FR-11一键启动与文档一条命令启动；README 写清依赖安装、启动命令、客户签到地址与工作人员地址及口令

名单清洗规则（FR-7 明细，必须按此执行）

情况处理方式
手机号经归一化后不是 11 位、或不以 1 开头视为无效记录，不计入应到人数，启动日志给出告警
同一手机号出现多条邀请记录（不同邀约人）只保留一条（第一条即可），应到人数按手机号去重后统计
姓名/公司前后有空格或全角空格统一去除首尾空白（含全角空白）
姓名相同但手机号不同是两个不同的人，不得按姓名去重

四、技术要求与约束

编号约束
TR-1必须能在普通笔记本上运行；不得依赖云服务、外部数据库、需要注册的第三方 API
TR-2服务需监听 0.0.0.0（或等价的局域网可达地址），使同一 Wi-Fi 下的手机能访问；不要求域名与 HTTPS
TR-3必须提供依赖清单与一条命令启动的方式
TR-4数据不得只保存在内存；重启后必须可继续签到并保持排重
TR-5签到时间必须由服务端生成；客户端传入的时间一律忽略
TR-6数据库操作需参数化（防注入）；工作人员接口必须做口令校验；客户名单不得通过未授权接口泄露
TR-7代码结构清晰（路由/业务/存储分层）、关键逻辑有注释、异常有处理、有运行日志（含名单导入告警）
TR-8全流程本地可跑通，无需外网；随题名单可直接用于自测

附录 C：可选加分项（每项 2–5 分，总分不超过 100 分）

  1. 桌牌二维码：自动生成带签到页面地址的二维码（可下载/打印），贴在签到台与桌卡上；
