发票 OCR 识别与汇总

练习模式 · 不限次数 · 提交后由大模型自动评分，达到 70 分即算通过

题目交付物随题材料提交答卷

一、业务背景

公司每月要把收到的增值税发票录入系统：发票代码、发票号码、开票日期、购买方、销售方、金额（不含税）、税额、价税合计，共 8 个字段。财务现在是手工逐张敲，问题很明显：

  • 发票多、字段多，敲错一位数字就要返工对账；
  • 同一张发票经常被重复提交（微信再发一遍），手工录入时不易察觉，导致重复入账；
  • 有些发票扫描件模糊/拍的不是发票，需要挑出来人工处理，不能污染汇总表；
  • 汇总要按销售方和月份两个维度统计，手工做透视表费时且容易漏。

云市场已经有一个增值税发票识别（OCR）接口（文档与示例代码随题给出）。希望写一个命令行程序：

扫描一个发票图片目录 → 逐张调用 OCR 接口 → 把识别结果整理成一张 Excel 汇总表（明细 + 销售方汇总 + 月份汇总 + 异常清单）。

二、任务与命令行契约

Bash python main.py --image-dir ./invoices --out ./发票汇总.xlsx \ --endpoint https://sdbillocrp.market.alicloudapi.com/invoice/ocr/query \ --appcode <你的AppCode>

参数必填默认值说明
--image-dir否./invoices发票图片目录（支持 .png/.jpg/.jpeg/.bmp）
--out否./发票汇总.xlsx输出 Excel 路径
--endpoint否生产地址（见第三节）OCR 接口地址，联调/验收时指向本地 Mock
--appcode否环境变量 OCR_APPCODE接口鉴权 AppCode
  • 必须支持 --endpoint 覆盖接口地址（否则无法在离线环境验收）；
  • 未提供 AppCode 时，必须明确报错并非 0 退出（不要静默产出空表）；
  • 图片目录不存在时同样报错退出。

三、OCR 接口说明

3.1 生产接口（随题给出的云市场服务）

Plain Text POST https://sdbillocrp.market.alicloudapi.com/invoice/ocr/query Header: Content-Type: application/x-www-form-urlencoded; charset=UTF-8 Authorization: APPCODE <你的AppCode> Body（form-urlencoded）: base64Str = 发票图片的 base64 编码字符串（与 url 二选一） url = 发票图片的下载地址，≤1024 字节（与 base64Str 二选一） ★ 二者都传时，接口优先使用 url

参考调用代码（题面给出的原始示例）：

Python import urllib.parse, urllib3 host, path = 'https://sdbillocrp.market.alicloudapi.com', '/invoice/ocr/query' http = urllib3.PoolManager() headers = { 'Content-Type': 'application/x-www-form-urlencoded; charset=UTF-8', 'Authorization': 'APPCODE ' + appcode, } bodys = {'base64Str': '增值税发票图片的base64编码字符串', 'url': 'url'} post_data = urllib.parse.urlencode(bodys).encode('utf-8') response = http.request('POST', host + path, body=post_data, headers=headers)

接口文档：https://market.aliyun.com/detail/cmapi00070088

appcode见测试数据

3.2 返回结构

JSON { "code": "10000", "msg": "成功", "reqId": "req-6f0a9c21", "data": { "invoiceType": "增值税电子普通发票", "invoiceCode": "044031900111", "invoiceNo": "12345678", "invoiceDate": "2026年06月01日", "invoiceAmount": "1000.00", "taxAmount": "130.00", "totalAmount": "1130.00", "buyerName": "华鑫科技集团", "sellerName": "云启科技有限公司", "checkCode": "0319 1122 3344 5566" } }

字段含义
code10000 表示识别成功；其它值为业务错误（如 20001 识别失败、20002 未识别到发票）
msg错误或成功提示，异常清单里要写进原因
data.invoiceType发票类型
data.invoiceCode / invoiceNo发票代码 / 发票号码
data.invoiceDate开票日期（格式不统一）
data.invoiceAmount / taxAmount / totalAmount金额（不含税）/ 税额 / 价税合计（可能是脏值）
data.buyerName / sellerName购买方 / 销售方名称
data.checkCode校验码

四、字段归一化规则

字段规则
发票号码 / 发票代码去首尾空白；发票号码为空 → 该发票计入异常清单
开票日期统一输出 YYYY-MM-DD；需兼容 2026年06月01日、2026.07.02、2026/09/01、2026-06-01、2026年8月5日；无法解析 → 异常清单
金额(不含税) / 税额去掉 ¥ ￥ , 空格 元 后解析为数值；缺失或无法解析按 0 计（不判异常）
价税合计同上解析；缺失或无法解析 → 异常清单（关键字段）
购买方 / 销售方名称去首尾空白
发票类型取 data.invoiceType，缺失时写 增值税发票

金额一律按数值写入 Excel（不要写成文本），保留 2 位小数。

五、去重规则

同一张发票的判定键 = 发票代码 + 发票号码：

  • 同一张发票在目录里出现多次（例如同一张发票被扫描/提交两遍、文件名不同）时，只统计一次（按文件名升序取第一次出现的），
  • 后续出现的登记到异常清单，原因写明重复发票（并尽量指出与哪个文件重复）。

编号约束
TR-1Python 3.9+；允许第三方库但必须提供依赖清单；必须能离线运行（除 Mock 外不依赖外网）

附录 A：注意事项

  1. 没有开 --endpoint 开关 → 离线环境直接连生产地址超时，验收全挂；
  2. 忘了 Authorization: APPCODE xxx 头 → 拿到 403；
  3. 用 multipart/form-data 上传 → 接口只认 form-urlencoded 的 base64Str/url；
  4. 把图片重新编码/压缩后再 base64 → 内容变了，Mock 命中不到（生产接口对图片内容也敏感）；
  5. 金额直接 float("¥2,260.00") → 抛异常或算错，必须先清洗 ¥ ￥ , 空格 元；
  6. 日期只认一种格式 → 2026年8月5日（无前导零）会解析失败；
  7. 重复发票没去重 → 汇总金额虚增（本题最典型的错）；
  8. 发票代码/号码被 Excel 当成数字 → 前导零丢失（044031900111 变成 44031900111）；
  9. 金额写成文本 → 财务无法直接求和；
  10. 单张失败就整体中断 → 后面所有发票都丢；
  11. 必须字段缺失仍写进明细 → 明细出现空号码/空金额行；
  12. url 与 base64Str 都传时，接口优先 url——如果你两者都传且 url 无效，会拿到错误响应。
