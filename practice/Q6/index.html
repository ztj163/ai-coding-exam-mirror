Q6

大会邀请函批量制作

练习模式 · 不限次数 · 提交后由大模型自动评分，达到 70 分即算通过

题目交付物随题材料提交答卷

一、业务背景

市场部要举办年度客户大会，会前需要给重要客户（老板 / 高管）逐一发出正式邀请函。

过去的做法是"一封通稿发所有人"，问题很明显：

  • 客户收到的信里没有任何与他自己行业相关的内容，像群发广告，转化率低；
  • 公司有明确的合规要求：对外正式函件的内容必须可解释、可复现、可审阅——不能每次生成都换一套说法，更不能出现"模型自由发挥"的表述；
  • 每年要发几十上百封，不可能一封封手写；市场部也没有设计师，排版要自动生成；
  • 邀请函是要发出去的 PDF 文件，中文字体、编号、日期、联系方式都不能出错；
  • 客户名单由客户经理收集，行业写法五花八门（"制造"/"智能制造"/"IT/互联网"/"新能源"…），还有重复登记、漏填姓名的。

所以市场部需要一个小工具：输入老板姓名、公司、行业（可选称谓），就能生成一封"行业定制"的邀请函 PDF；支持按名单批量生成。

内容来源已经准备好了：一套行业话术库 + 一封邀请函模板（都由市场部人工审阅定稿）。程序要做的只有一件事：按规则把两者拼起来，渲染成 PDF。

二、任务目标

做一个规则驱动的邀请函生成器：读随题的模板与行业话术库，按名单批量生成个性化 PDF 邀请函与清单。

验收口径：用随题名单执行你的命令 → 输出目录里出现每人一份 PDF（重复登记与空姓名已正确跳过）；打开任意一份，中文正常显示、占位符无残留、正文包含该客户的姓名/称谓/公司/大会信息以及其所在行业专属的四段话术；把行业换成另一个，话术随之切换；再跑一次，内容完全一致。

三、功能需求

编号需求验收要点
FR-1单份生成输入 姓名 + 公司 + 行业（称谓可选）→ 输出一份 PDF
FR-2批量生成读取邀请名单 CSV，为每位老板生成一份 PDF，并输出 manifest.csv 清单
FR-3行业归一化按 行业映射.csv 把名单里的行业写法映射为标准行业；映射表中没有的行业，兜底使用标准行业 其他，并在日志中告警
FR-4行业话术匹配从 行业话术.csv 取出该标准行业的四段话术（行业观察 / 参会价值 / 行业案例 / 邀约语）填入正文；不得串用其它行业的话术
FR-5称谓规则① 名单中该客户的「称谓」字段非空 → 直接使用；② 否则姓名已以「总/女士/先生…」结尾 → 原样使用（不得出现"张总总"）；③ 否则按复姓表取复姓 + "总"（如 欧阳锋 → 欧阳总），单姓取姓氏 + "总"（如 张伟 → 张总）
FR-6模板渲染用 邀请函模板.txt 渲染正文；所有 {占位符} 必须替换，不得残留 {}
FR-7编号规则邀请函编号 = INV- + 会议日期（YYYYMMDD）+ - + 四位流水号（从 0001 起，按名单顺序），编号必须唯一
FR-8中文 PDF 输出A4 页面；中文字体必须嵌入（换台电脑打开也不应出现方框/乱码）；排版不得溢出到页外；正文可被 PDF 文本提取工具正确读出
FR-9名单清洗姓名为空的记录跳过并告警；同一「姓名 + 公司」重复登记只生成一份并告警
FR-10命令行与文档提供 CLI（见下方契约）；README 写清依赖安装、生成命令、输出目录与文件命名规则、字体来源

命令行契约（必须实现，用于自动验收）

Bash # 批量 <启动命令> --input <邀请名单.csv> --outdir <输出目录> [--date YYYY-MM-DD]

# 单份

  • --date：签发日期（YYYY-MM-DD），默认当天；编号中的日期取会议日期（来自 大会信息.json），与签发日期无关；
  • 输出文件命名：邀请函_{姓名}_{公司}.pdf（文件名中的非法字符需替换）；
  • 必须输出 manifest.csv，表头为：编号,姓名,称谓,公司,行业,文件名（行业 填标准行业）。

占位符清单（模板里会出现，必须全部替换）

{会议名称} {会议时间} {会议地点} {签到时间} {会议议程} {主办方} {报名链接}

{邀请函编号} {签发日期} {姓名} {称谓} {公司} {行业} {客户经理}

{行业观察} {参会价值} {行业案例} {邀约语}

四、技术要求与约束

编号约束
TR-1禁止调用任何 AI / 大模型 / 在线翻译或文案服务生成邀请函正文；正文必须来自随题模板与话术库的规则拼装（允许本地字符串处理，不得联网请求模型）
TR-2必须能在离线环境运行；不依赖云服务、外部数据库
TR-3允许使用任意 PDF 库（fpdf2 / reportlab / PyMuPDF / jsPDF 等）与任意语言；必须提供依赖清单
TR-4必须解决中文显示：随题提供了中文字体（data/fonts/NotoSansSC-Regular.ttf，OFL 授权），也可使用自带字体；字体需嵌入 PDF
TR-5结果可复现：同一名单 + 同一签发日期，重复运行生成内容一致（不得随机化文案、编号或排版）
TR-6生成的 PDF 必须可被标准 PDF 工具打开并提取文本（不出现乱码/空白页）
TR-7代码结构清晰（读取规则 / 规则匹配 / 渲染 / 输出分层），关键逻辑有注释，异常有处理，有运行日志与告警
TR-8全流程本地可跑通；随题名单可直接用于自测
