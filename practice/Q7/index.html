Q7

报销数据汇总

练习模式 · 不限次数 · 提交后由大模型自动评分，达到 70 分即算通过

题目交付物随题材料提交答卷

一、业务背景

财务每月要汇总各部门的报销金额。报销系统导出的是一份 CSV，字段有单据号、部门、金额（整数元）、审批状态。

汇总本身不复杂，但麻烦在于导出数据并不干净：有金额写成 abc 的、有部门漏填的、有金额带负号的、状态有 待审批/已驳回 的……财务同事每次用 Excel 手工筛，容易出现口径不一致（比如把 -10 也加进了总额）。

现在需要一个命令行小工具：读入导出的 CSV，输出一份结构化汇总结果，口径固定、结果可复核，方便财务直接拿去核对。

二、任务

编写一个 Python 程序，通过命令行执行：

Bash python main.py expenses.csv result.json

  • 第 1 个参数：输入的报销 CSV 文件路径
  • 第 2 个参数：输出的 JSON 文件路径
  • 程序需把汇总结果写入该 JSON 文件，UTF-8 编码、合法 JSON

三、输入说明

CSV 含表头，共 4 列：

列名含义说明
bill_id单据号不参与校验、不去重
department部门可能为空或带首尾空白
amount报销金额整数元，不涉及角、分；可能是不合法内容
status审批状态可能为 已通过 / 待审批 / 已驳回 等

随题样例 data/expenses.csv：

Plain Text bill_id,department,amount,status B001,行政,120,已通过 B002,销售,300,已通过 B003,研发,250,已通过 B004,行政,80,已通过 B005,研发,0,已通过 B006,销售,abc,已通过 B007,,50,已通过 B008,销售,-10,已通过 B009,行政,999,待审批 B010,销售,200,已驳回

四、输出契约

输出为 UTF-8 编码的合法 JSON，必须恰好包含以下 5 个字段（多余字段视为不合格）：

字段类型含义
valid_count整数有效记录数
invalid_count整数已通过但部门或金额无效的记录数
ignored_count整数状态不是「已通过」的记录数
total_amount整数有效金额总和
department_totals对象部门名（字符串）→ 该部门整数总金额；只包含有有效记录的部门

硬性要求：

  1. 整数必须是 JSON 数字——不能是字符串（"750"）、浮点（750.0）、布尔值；
  2. department_totals 的值也必须是整数；
  3. JSON 对象的键顺序、缩进、中文是否转义都不影响判分；
  4. 编码必须是 UTF-8（建议不带 BOM）。

示例（仅示意格式）

输入：

Plain Text bill_id,department,amount,status A1,行政,100,已通过 A2,研发,50,已通过 A3,销售,abc,已通过 A4,行政,30,待审批

输出：

JSON { "valid_count": 2, "invalid_count": 1, "ignored_count": 1, "total_amount": 150, "department_totals": { "行政": 100, "研发": 50 } }

五、判定规则（必须严格执行）

5.1 状态判定

  • status 去掉首尾空白后必须恰好等于 已通过 → 进入后续判定；
  • 其他任何情况（待审批、已驳回、空、APPROVED、已通过 之外的未识别值）→ ignored_count 加 1；
  • 注意：" 已通过"（前后有空白）算已通过。

5.2 已通过记录的部门与金额判定

  • department 去掉首尾空白后为空 → 该记录计入 invalid_count；
  • amount 去掉首尾空白后必须匹配半角非负整数 ^[0-9]+$，否则计入 invalid_count；
  • 两者都有效 → 该记录为有效记录：valid_count 加 1、total_amount 累加、department_totals[部门] 累加。

5.3 金额有效性的具体边界

amount 原值是否有效说明
120✅ 有效正常整数
0✅ 有效0 是有效金额
007✅ 有效前导零按十进制解析为 7
" 80 "（带首尾空白）✅ 有效去空白后有效
9999999999✅ 有效不限整数大小，不得溢出
-10❌ 无效负数
-0❌ 无效带负号
+50❌ 无效带正号
12.5❌ 无效有角分/小数
1,200❌ 无效千分位分隔符
¥120❌ 无效货币符号
１２０（全角数字）❌ 无效必须是半角数字
abc / abc123❌ 无效非数字
空值❌ 无效缺失

5.4 其他约定

  • 空行（整行都没有内容）直接跳过，不计入任何计数；
  • 不按 bill_id 去重：同号多条记录逐条统计；
  • department 做去首尾空白后作为汇总键（"行政 " 与 "行政" 视为同一部门）；
  • 表头字段名允许前后空白（如 " bill_id " 应能识别）；
  • 文件可能为 UTF-8 with BOM，需要兼容；
  • 行尾可能是 \n 或 \r\n，都需要兼容。

5.5 错误处理

以下情况必须报错退出（退出码非 0，建议 2），错误信息写到 stderr（标准错误），不要求生成结果文件：

  • 命令行参数个数不对；
  • 输入文件不存在或不可读；
  • CSV 缺少必需列（bill_id / department / amount / status 任一缺失）。

六、技术要求与约束

编号约束
TR-1Python 3 +；标准库即可完成，如用第三方库须提供依赖清单
TR-2必须可以离线运行，不得联网调用任何服务
TR-3禁止硬编码：不得把样例结果（750、5、3、2 等）写死在代码里
TR-4结果必须由程序计算得出，可重复运行且结果一致
TR-5代码结构清晰、关键逻辑有注释、异常有处理
TR-6输出必须符合第四节契约（字段恰好 5 个、整数为 JSON number、UTF-8）

附录 B：注意事项

  1. -10 不要当成有效金额（负号不合法）——这是最常见的口径错误；
  2. 0 是有效金额，会被计入 valid_count，并且该部门（研发）会出现在 department_totals 里，值为 0；
  3. department_totals 只包含有有效记录的部门：无效记录（如 B007 部门为空）不产生键；
  4. 整数不能输出成浮点或字符串：json.dump 一般没问题，但如果你用了 float() 或 str() 就会挂；
  5. 不要用 float 解析金额（会引入精度问题，也可能把 12.5 当成有效）；
  6. CSV 可能有 BOM，用 encoding="utf-8-sig" 读取最稳；
  7. status 前后空白要处理，否则 " 已通过" 会被错判为 ignored；
  8. 缺列时要报错退出，不要让程序崩溃给出堆栈当作"正常退出"。
